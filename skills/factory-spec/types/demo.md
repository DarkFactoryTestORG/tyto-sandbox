# Demo interview

Use this type for a visible colour change in the demo application.

Ask for the intended outcome, scope and observable result, a few questions at a time. Read the repository standards and code yourself; do not ask for paths or repeat decisions already covered by standards. Pin down failure modes and edge cases before drafting. Never include secrets or environment values. Use the skeleton headings and lint the draft. Prefer smoke for a changelog-only change.
