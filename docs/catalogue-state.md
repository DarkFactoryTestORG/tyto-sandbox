# Catalogue state

Plotline is built in the **"before" state** of every worked example in the factory's issue
catalogue (`docs/issue-types.md`, _Examples_), so each example can be filed as a real issue. This
table is the acceptance check for that: every example, whether its "before" state holds, and
where. Paths are from the repo root.

| **#101** bug/logic: due dates shift back a day west of UTC              | Yes. The bug is planted. Users have a `timezone`; due dates are stored as `timestamptz`; `parseDueDate` (line 41) takes UTC midnight and shifts it by the user's offset, so a New York user's 2026-11-03 reads back as 2026-11-02. Users east of UTC are unaffected.                                                                                                                           | `apps/api/src/tasks/dates.ts:41`, `PATCH /tasks/:id` in `apps/api/src/tasks/tasks.service.ts`, `packages/db/src/schema.ts` (`tasks.due_date`, `users.timezone`), due-date field in `apps/web/src/components/EditTaskModal.tsx`                                                                                                                     |
